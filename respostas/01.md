## 🎯 1. OBJETIVO DO REQUISITO
- **Qual é o escopo central da feature?**
  Transformar o `byte.burger` em uma aplicação web progressiva (PWA) de arquitetura *local-first*, eliminando todas as anomalias de compilação, normalizando imports/casing e dotando a aplicação de persistência local soberana via `localStorage` e suíte de testes unitários automatizados com Vitest.

## ⚖️ 2. DECISÕES DE DOMÍNIO E ARQUITETURA
- **Qual a abordagem de persistência escolhida?**
  Local Storage API do navegador para o estado do usuário, progresso de carreira (XP), saldo de pontos e histórico de pedidos. Sem necessidade de banco de dados remoto ou backend ativo.
- **O que fazer com a dependência `@supabase/supabase-js`?**
  Remover do `package.json` para purgar código morto.
- **Como tratar a divergência matemática de XP entre Home e Loyalty?**
  Sincronizar a Home para utilizar a mesma função de cálculo de tier relativo (`xpInLevel / xpToNext`), eliminando o valor estático hardcoded de 68%.
- **Qual framework de testes utilizar?**
  Vitest + React Testing Library + JSDOM, com foco em TDD estrito e mínimo de 3 cenários por suíte (happy path, edge case, error path).
- **Como tratar os problemas de portabilidade Linux?**
  Renomear `vit.config.ts` para `vite.config.ts`, `tsconfig.app.js` para `tsconfig.app.json` e normalizar o casing de `NavBar.tsx`, `Toasthost.tsx`, `home.tsx`, `menu.tsx`, `loyality.tsx`.

## 🔒 3. CRITÉRIOS DE ACEITE

2. Atualizar a página (F5) não apaga o carrinho nem o XP do usuário.

4. Resgatar recompensa consome pontos reais do saldo do usuário.
